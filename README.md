# Fitness Club

Staff portal for a fitness club: clients, memberships, visits, trainers, rooms, bookings, expiry notifications and reports.
.NET 10 API + React UI + SQL Server, all in Docker.

## Run

Needs Docker Desktop. On Apple silicon, SQL Server runs under amd64 emulation.

```sh
cp deploy/.env.example deploy/.env                          # works as is for local dev
docker compose -f deploy/docker-compose.yml up --build -d   # first start takes a few minutes
docker compose -f deploy/docker-compose.yml ps              # wait until all three are healthy
```

| What | URL |
|------|-----|
| UI | http://localhost:8081 |
| API docs (Scalar) | http://localhost:8080/scalar |
| Health | http://localhost:8080/health |

Sign in with the same test accounts as the live demo (details in [Demo Data and Users](docs/Code/Demo%20Data%20and%20Users.md)). The API migrates and seeds mock data on first start.

Stop with `docker compose -f deploy/docker-compose.yml down`. Add `-v` to wipe the database too.
To run without Docker, see `api/CLAUDE.md` and `ui/CLAUDE.md`. All settings are in `deploy/CLAUDE.md`.

## Patterns used

**Backend**
- **Clean Architecture:** Domain ← Application ← Infrastructure ← Api. Architecture tests (NetArchTest + Roslyn) enforce it.
- **DDD:** sealed aggregate roots with private setters and factory methods; value objects in `Domain/SharedKernel` (`Money`, `PhoneNumber`, `TimeSlot`…); a domain service (`SessionScheduler`); `DomainException` for broken rules.
- **Repository + Unit of Work:** repository interfaces in Domain, `IUnitOfWork` in Application, EF Core implementations in Infrastructure. One `SaveChangesAsync` per use case.
- **Service layer + DI:** controllers depend only on `I{Name}Service`; each layer registers itself (`AddApplication()`, `AddInfrastructure()`).
- **DTOs + two-layer validation:** request/response records with DataAnnotations for shape, entities for business rules.
- **Optimistic concurrency:** a shadow `Version` token on every aggregate; a stale save → 409.
- **Exception → Problem Details:** one handler maps exceptions to RFC 7807 responses (400/404/409/500).
- **Separate read side for reports:** `IReportQueries` queries the database directly instead of loading aggregates.
- **Strategy / adapter:** `INotificationSender`, currently `LoggingNotificationSender`, swappable for email/SMS.
- **Scheduled job:** a Hangfire recurring job sends expiry notices daily.
- **Injected clock:** `TimeProvider` instead of `DateTime.UtcNow`, so time is testable.
- **Role-based auth:** Auth0 JWT, an "authenticated" fallback policy, `[Authorize(Roles = …)]`.

**Frontend**
- **Feature folders:** `ui/src/features/*`.
- **Contract-first API client:** generated by Orval from the API's OpenAPI document.
- **Server state:** TanStack Query.
- **Route guards:** `RequireRole`.
- **Reverse proxy:** nginx serves the UI and proxies `/api/` to the API, so there's one origin and no CORS.

**Tests:** unit tests for domain rules, integration tests on real SQL Server (Testcontainers), and architecture tests.
